We use the print out to explain why a certain option is true:
a. # x = 78163 | y = 78161
b. # x = 78164 | y = 78162
c. * x = 0 | y = 78162 (78162 is the child of master process), # x = 78163 | y = 78161
(78161 has another child 78163). Due to the code structure, only the master process
can have two children. With only 4 processes created, we can deduce that 78161 is the
master process, hence is the only process with two children.
d. # x = 78163 | y = 78161
e. By process of elimination 😊. Or, by the same logic in (c), we have enough info
(code + print out) to deduce the entire family tree.

8. Given the following pseudo-code
// CPU Bound Code
// takes about 300ms
if (fork() != 0) { // Parent
// CPU Bound Code
// takes about 200ms
} else {
// Child Process
// CPU Bound Code
// takes about 100ms
}
// Both Parent and Child ends here
Which one of the following scheduling setups allow parent process to finish before the
child process?
a. MLFQ with 200ms time quantum, where fork() implementation requires reading
binary file from secondary storage.
b. Non-preemtive FCFS, where fork() implementation requires reading binary file from
secondary storage.
c. Pre-emptive SRT, where fork() implementation is purely CPU bound.
d. Pre-emptive Priority scheduling, where the child has higher priority and the fork()
involves only CPU bound instructions.[Updated during midterm]
e. None of the above
ANS: b or e (alternative)
The info about the fork() implementation is not really a red-herring. Rather, it shows the
potential of fork() incurring an I/O (which gets the parent process blocked). We will explain
why other options wont work briefly:
a. By the time the parent reaches fork(), it would have lower priority (as early 300ms
will see a demotion in priority). As the newly created child will have the highest
priority, the parent wont secure the CPU to finish execution before the child.
b. Parent blocked but will need to come back to running to finish fork(), which creates
the child process. Since this is FCFS, the parent will just continue to the end,
finishing before the child.
c. Child has shorter remaining CPU time after fork(), so will pre-empt the parent.
d. With pure CPU work in fork(), the parent will continue execution. However, since
this is a pre-emptive scheduling, child with higher priority will kick out the parent,
finishing the work before the parent.

9. Evaluate each of the following statements regarding the overhead of Context Switch.
Overhead refers to the time needed to perform the context switch of one process to
the other.
On processor with more general purpose registers, more time is needed for
a
context switching.
On a platform using purely user thread implementation, the number of
b
threads in a process does not impact the overhead of context switch.
c Processes with more stack frames incurs larger overhead of context switch.
Given that process only records their parent PID, but not their child PID(s);
d number of child processes in a process does not impact the overhead of
context switch.
Ans:
a. TRUE. Register is part of the hardware context and need to be saved / restored. So,
more reigsters == more time needed.
b. TRUE. Kernel is not aware of thread, i.e. there is no different whether a process has
thread or not.
c. FALSE. Only $SP, $FP is saved regardless of size of stack region.
d. TRUE. The clarification is given as it is possible to keep the child process IDs, then more
child processes could mean more info to save / restore. If only fixed amount of info is
needed, there is no difference in the context switching time.

11. Given the following pseudo code fragment:
Semaphore S = 4; //S has an initial value of 4
//each process runs the following
Wait(S);
// Code section A
Signal(S);
Evaluate the following statements:
a There cannot be more than 4 sleeping processes waiting on S.
At any point in time, there cannot be more than 4 processes executing in the
b
“Code Section A”
c Code Section A is not a critical section.
If there are more than 4 processes running this code fragment, the value of S
d
can go beyond 4 eventually.
Ans:
a. FALSE. You can have any number of processes waiting of S (after it’s value reaches
0, e.g.waited four times by processes that are still working in section A).

value (as there is no free signal() in the code without a wait()).

section.
